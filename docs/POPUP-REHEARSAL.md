## 0 · Before anybody leaves the club

### Pair the staff phones — do this first
Each phone takes about a minute.

1. On a laptop: **Admin → Kiosk & Staff PINs**.
2. Device name: **the name of the person carrying it** — "Chau's phone", not "Phone 2".
   That label is what the run sheet's heartbeat shows you all evening.
3. Kind: **Pop-up staff phone**. Leave the room blank; the database refuses one.
4. A six-character code appears. On the phone, open
   `therampantclub.com/kiosk/pair/go?code=XXXXXX` — it pairs by opening the link,
   with no typing and no button to miss.
5. The phone lands on the sign-up screen. **Tap ◆ (top left) → the staff member's own
   PIN → "Door list"** to check it reaches the door too. One pairing does both jobs.

A pop-up phone can open the sign-up and the door list **and nothing else** — not the
board, the finder, the menus, the member pad, or the club's own door iPad. That is
deliberate: it is a phone that gets handed to strangers.

> **If a phone dies on the night:** any paired **room tablet** can take sign-ups as a
> fallback (it cannot open the door list). Or issue a new pairing code — it takes a minute.

If the label says **"Storing…"**, give it a moment. If it says **"NOT ready offline"** in red,
the tablet has not stored itself — reload the page while still on the wifi. If it still will
not go green, that tablet is not safe to take; see the note below.

> **The old rule, kept for one case only.** A tablet that is **not** showing
> "Ready offline" has nothing stored and **must not be reloaded at the Palace** — with no
> signal it will come back blank and stay blank until the router returns. Only a tablet
> showing "Ready offline" is safe to reload there.

### If you change the bottle list after a tablet has been warmed

The 40 bottles travel **inside the page**, so a tablet keeps serving the list it stored
until it fetches a fresh copy.

**After saving a new list in the admin, every tablet needs one reload while it is still on
the club's wifi.** Open the finder, pull down to refresh (or close and reopen the page), and
wait for "Ready offline · N whiskies" to show the **new** number. If the number is the old
one, it has not picked up the change yet — reload again.

A tablet already at the Palace, with no signal, **cannot** pick up a changed list. Decide the
40 before the tablets leave.

## 1 · The rehearsal itself

Work through it in this order. Every one of these has been tested through the real
routes, but none of them has been tested **by the people doing it on Friday**.

### Sign-up, on a staff phone
- [ ] Take a booking end to end. Read the confirmation screen out loud — **turn the phone
      round and show it to whoever is playing the guest.**
- [ ] Do it again with no email address. It must still work.
- [ ] Type an email wrong on purpose. Screen 3 shows it back large; the booking still goes
      through. **A typo never costs a place.**
- [ ] Switch to **VN** and do one in Vietnamese.
- [ ] Walk away for 30 seconds. The form must clear completely.
- [ ] Swipe back. It must start a new guest, not show you the last one.
- [ ] Tap ◆ and try a **wrong** PIN. It must refuse.

### The door, on a different phone
- [ ] Scan a ticket QR from the confirmation email. (Camera works on Android; **iPhones
      type the code** — that is a browser limitation, not a setting.)
- [ ] Type an 8-character code by hand.
- [ ] Search a name. Search an email.
- [ ] Admit a party of two but say **only one is here**. Then correct it to two.
- [ ] Tick the wrong person on purpose, then **Undo**.
- [ ] Scan a code that does not exist. It must say "Not on tonight's list" — not an error.
- [ ] **Two phones at once on the same guest.** One says "In you come", the other says
      "Already admitted by [name] at [time]". Do this one twice; it is the thing most
      likely to happen on Friday.
- [ ] **Turn aeroplane mode on.** Admit somebody. It says "saved on this phone". Turn it
      back off. Watch the queue count go to zero, and check the run sheet shows them in
      at the time you ticked, not the time it synced.
- [ ] Add a **walk-up**.

### The run sheet, on a laptop
- [ ] Watch a tick from the door appear within a few seconds.
- [ ] Check every paired phone shows **online** in the heartbeat.
- [ ] Raise the cap. Check that anybody on the waiting list is promoted **and emailed**.
- [ ] Lower the cap below what is booked. **Nobody is cancelled** — the session is just
      marked over. Confirm that is what you see.
- [ ] Pause bookings. Try a sign-up (refused). Try the door (still works). Unpause.
- [ ] Move somebody to another session. Cancel somebody.
- [ ] **Print the door sheets** (`/admin/popup/print`) and put them in the folder. One A4
      page per session. This is the fallback if everything else fails.

### The evening running late
- [ ] Shift all remaining sessions by 15 minutes. Check it refuses to move a session into
      the past, and that the session **already running** is left alone.
- [ ] Send the notice. Only the people whose time changed should get it.
